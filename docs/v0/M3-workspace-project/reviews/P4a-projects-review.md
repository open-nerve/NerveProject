## 7. 已知限制

- `createProject` 由工作区 `FOR SHARE` 之下做出的判定确认创建者，不读 `ShareMembers` 对创建者的回答；成立的前提是约定二：每条结束成员关系或改角色的路径都先以 `FOR NO KEY UPDATE` 锁工作区。
- 连带写入调用者在加锁之前读的一个时刻（设计 3.3）。P4a 里没有不持工作区锁就改项目行的写；从 P4b 起，项目级的写只持项目锁，被连带改写的行的 `updated_at` 可能比它之前的值早一次锁等待的长度（F-M3）。
- `getProject` 对不存在的 id 只做一次查询，对存在而看不到的项目再读角色和项目的事实：已知一个项目 id 的人可以从时间上判断它是否存在（id 是 UUIDv7，有 62 个随机位，必须先知道 id；设计 8.2 接受，F-M5）。
- 工作区的成员能经标识的检查或建项目的 409 知道私密项目的标识和名称（工作区范围内唯一，与 Plane 相同）；访客和外人在任何查询之前被拒绝。
- 停用的账户在 P6 之前仍可以被指定为负责人，只要它仍是工作区的有效成员（P6 的停用结束成员关系，交错 15）。
- 两处降级的加锁顺序在 P4a 由组合出的测试核对"等工作区成员行时还没有锁项目"；真正与之竞争的写（P4b 的添加、加入）到交错 17 才有。
