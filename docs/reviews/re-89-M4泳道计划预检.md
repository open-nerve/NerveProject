## 3. 核对过、没有问题的

**语义相等（没有找到反例）**

- 键数组的四种情形都只挑出一行：`ARRAY(SELECT …)` 从不为 NULL，空时 `unnest` 零行，`LEFT JOIN` 补一行、键与序号都是 NULL → `'none'`、`coalesce(n,1)=1` 为真；`ARRAY[to_char(NULL…)]` 是含一个 NULL 元素的数组，一行、序号 1、键 NULL → `'none'`；`CASE` 不命中（泳道的 `project_id`）得 NULL 数组，`unnest` 零行，同空数组；多值时序号 1..n，恰有一行为 1。第二个 `LATERAL` 只依赖 `i`、`s`，规划器调换两个展开的次序也不影响序号。
- 组总数：旧式在只按组展开的流上数，一个工作项在组 g 下一行；新式数 g 分区里 `first_lane` 的行，一个工作项在 g 下的每一个组行恰有一行泳道序号为 1。泳道对称。格总数与行集：新流每个工作项 |G| × |L| 行，与旧式两条流按 `id` 连出来的行相同。
- 重复键（假设能出现）：组键 {a,a}、泳道 {x,y} 时，旧式组 a 记 2、泳道 x 记 1、格 (a,x) 记 2，新式逐项相同。
- `total` 仍在 `counted`；只看自己的过滤在 `filtered`；`numeric_keys`、`keyed`、`ranked` 的排序与游标谓词、最终投影与 `ORDER BY` 都在改动范围之外；空页回退的总数仍在游标与组键选择之前算出。
