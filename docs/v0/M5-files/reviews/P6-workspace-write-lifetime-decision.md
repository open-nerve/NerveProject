## 1. 已复现的行为

使用实际 RootStore、WorkspaceRootStore、IssueRootStore、UploadSession、ApiClient；只有网络应答由现有 FakeNerve 控制。没有修改产品代码或权限守卫，没有容器或后端环境参与。

顺序是：管理员发出工作区 logo 的 PATCH → 暂留响应 → 完整工作区目录返回新角色/新图 → 交付原 PATCH 的旧成功响应。结果如下：

| 目录中的新事实 | 原上传是否保持失效 | 迟到 PATCH 后的规范 store | 断言 |
| --- | --- | --- | --- |
| 管理员 20 → 普通成员 15 | 是 | 角色被改回 20，logo 变回旧上传；新建上传会话又被判为可写 | 失败 |
| 20 → 15 → 20，恢复后的目录已有另一张图 | 是 | 最新 logo 被旧上传覆盖 | 失败 |
| 工作区从目录移除 | 是 | 仍为空，不重新插入旧工作区 | 通过 |
| 原工作区移除，同 slug 的新 UUID 出现 | 是 | 新 UUID 及其图标保持 | 通过 |

实际结果为 **2 failed / 2 passed**，失败是值与行为断言，不是编译或环境错误。[完整日志](evidence/P6-workspace-write-lifetime/probe.log)、[收据](evidence/P6-workspace-write-lifetime/receipt.json)、[源码与输入身份](evidence/P6-workspace-write-lifetime/identity.json)、[探针原文](evidence/P6-workspace-write-lifetime/probe.test.ts.txt)已固定。4466 个非文档输入在执行前后 hash 一致。

证据边界：证明的是前端规范权限事实和图片状态被迟到响应覆盖，**没有证明后端允许越权写，也没有声称真实浏览器已经泄露图片**。后端仍执行自己的授权。前端把普通成员重新当管理员，已违反当前权限事实合同，且会影响其他依赖工作区角色的页面。

## 2. 根因与边界

`WorkspaceRootStore.updateWorkspace`（`core/store/workspace/index.ts`）在网络成功后无条件执行 `list.confirm(replaced(workspace))`。返回的是整条 Workspace，含调用者 role。`oneAtATime` 只串行本会话的写，不能给别的管理员操作、目录读取与延迟网络交付排序。

T2 的上传生命期已经正确失效，T4 的绑定后检查也会阻止旧弹窗完成回调；但宿主 store 在这些 UI 检查之前已发布旧整行。继续在组件里加一次角色判断或忽略 toast，不能保护其他 store/页面的事实来源。`replaced` 已按 UUID 替换而不插入，所以缺席和同 slug 新 UUID 两个控制组通过，不应把已存在的身份保护误报成问题。

这是 M3 的工作区规范数据发布、M4 的统一权限代次和 M5 的宿主绑定共同遵守的合同；超出 PC1 仅扩展项目可见性签名的批准范围。按 [03 §1](../../claude_to_gpt/03-rules-and-pitfalls.md#1-负责人的纪律)“跨模块协同调整……等我决策”，提交当前完成工作与此记录后暂停依赖实施。

## 3. 推荐 A：在宿主发布边界核对原权限生命期

先同步 M3/M4/M5 的相关说明与 P6 spec/plan，再实施：

1. `WorkspaceRootStore` 声明小的工作区写回有效性接口，由 RootStore 接到 **现有 IssueRootStore/PermissionReads** 的单调代次。工作区 UUID、成员权限代次与 root 是否仍有效共同决定结果能否发布；不引用 asset 上传控件，不再建观察器或权限缓存。
2. 核对覆盖请求排队、真正发出、成功/失败交付与已确认写在旧读上的重放。权限曾经改变，即使后来恢复为同一角色，原操作仍过时；过时回包不得覆盖当前目录或触发旧视图的完成/错误反馈。
3. 增加窄的工作区范围查询，明确只跟随本工作区身份与成员权限变化。不能直接把现有 `current(..., projectIDs=[])` 当纯工作区查询，因为它还包含该工作区的项目变化；无关项目变化不得取消图标写。
4. 保留有效范围内现有“已确认写胜过旧读”的调和规则。不修改通用 Reconciled 的默认行为，不放宽任何既有权限守卫，不改后端协议/数据库/授权角色，不扩成全局 store 重构。
5. 失效只禁止发布到前端当前事实，不声称撤销服务器已接收的写。已发送请求可能已成功；当前页面按有权宿主读取取得新事实，不自动重发写。

收益：修复发生覆盖的宿主发布边界，工作区名称/规模/时区和 logo 共用正确规则；统一失效仍只有一个所有者。职责上，WorkspaceRootStore 决定数据是否进入自己的规范缓存，IssueRootStore 提供权限有效期，图片控件只负责操作反馈，符合现有 SOLID 取向。

风险/代价：会调整工作区 store 的异步完成语义和组合根接线，须同步现有资料表单；丢弃失效成功后可能需要一次合法目录读取才能展示服务器最终状态。必须避免用全局代次过度取消无关操作，也不能把普通网络拒绝误当过期静默吞掉。

这比修改通用 Reconciled 或另建 asset 观察器范围更小；比只合并 `logo_asset_id` 字段更完整，后者既无法阻止权限 ABA 的旧图片覆盖，也没有保护现有普通工作区更新。当前建议仅限定已证明的工作区写发布问题；项目及其他宿主继续按各自任务验证，不提前扩展实现。
