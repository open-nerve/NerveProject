## 2. 核对过的性质

- **数字**：
  - 计数：五个状态组经同一个 `Counts.add` 合成总数；状态不在项目的状态里或不在五组即错误（500），`ProgressOf` 与 `CountsOf` 共用。
  - 分布：已取消跳过；多个负责人/标签的工作项每个 id 计一次；没有的进 `nil` 行；只有总数大于 0 的行；按 `uuid.UUID.Compare`（同 Postgres 与文本序），`nil` 行最后；已完成按状态组。
  - 燃尽：缺任一日期、开始晚于结束、跨度超过 3660 天为 `nil`；点覆盖开始到结束；今天（项目时区）之后为 `nil`；完成日是 `completed_at` 在项目时区的日期，已完成组缺完成时刻的从第一天起算，别的组带过时完成时刻的不燃尽；`scope` 不含已取消。
  - 冻结的编解码：字段名同接口；解码严格（解码再编码、以 `UseNumber` 比对），拒绝未知、缺失、大小写不同的键与 `null` 列表；列表的语句去掉分布与燃尽，`DecodeFrozenCounts` 只收七个键。
  - HTTP 与 OpenAPI：各 schema 的字段、可空与次序同领域的 JSON；数组从不为 `null`；根契约列出三条路径；`Cycle`/`Module` 与各写入的回答不变。
- **可见范围**：`held.viewer` 只在 OwnOnly 时为调用者；两个 `/progress`、两种列表（计数与负责人）都传它；OwnOnly 不读冻结；冻结与转移用全部工作项。issue 的五条统计语句：归属与工作项未删除、未归档、本项目，`viewer` 谓词同 `list_issues.sql:24`，负责人与标签数组去重且未删除；不连 `cycles`、`modules`、`states`（`TestSQLCSchemaScope` 覆盖新文件，守卫未放宽）。
- **锁、事务与时钟**：
  - 读：一个只读快照，次序为状态组 → 工作项 → 冻结 → 时钟。
  - 冻结任务：候选不加锁、以 UTC 的日界定（真超集）；每项目 `JobTx` → 项目行锁（已删除跳过）→ 时钟 → 结束日早于本地今天的未冻结迭代 → 只在为空时写；部分提交；不写最后修改；部分索引与候选语句的条件一致。
  - 转移：`Locks.run`（预检 → 写闸门 → 事务 → 项目行锁 → 重读），锁下按 spec 的次序判定，时钟在最后一把锁之后；已冻结的不重算，否则用移动前的数字与同一时钟冻结；issue 一侧只锁归属行（`FOR NO KEY UPDATE OF r`），软删加插入，每个工作项一条 `CycleMoved`，`MarkChanged`，不发布事件。锁序项目 → `cycles` → `cycle_issues` → `issue_activities` → `issues`；其余写者都先取项目行，偏好取 `FOR SHARE`，没有会挡住外键 `KEY SHARE` 的 `FOR UPDATE`；只有 `FreezeCycle` 写该列，没有丢失更新。
- **架构**：端口由消费方声明；`issue.Provide` 只用连接池交出两个端口；项目端口经复用扩展、无新 SQL；`bootstrap` 转换并原样传递 ctx；模块互不导入；最大的手写文件 379 行；没有开关、桩、兼容别名或死代码；生成物经 `make gen`。
- **测试**：台账的 RED 与变异和代码一致；事后写的组合测试（T5–T7）有拆线或桩的 RED 与命中它们的变异；T10 的五组交错在两种去锁变异与“锁前读时钟”的重放下都失败；T11 的 154 格与“访客看全部”变体终于钉住转移的 `cycle.write`。回归的边界守住：既有测试只改类型与调用序列；`seedCycles` 的日期与 `newPlanningRouteWith` 的拆分按主控批准。e2e 的四个故事时区锚在离正午最近的整点 `Etc/GMT±N`，轮询数据库等 2 秒的冻结任务，G7 接受任务或转移先冻结，数据库一侧以独立的 SQL 核对计数。
- **配置与任务**：`freeze_interval` 的键、校验、日志键与环境覆盖，三种环境的期望，六处周期种类清单，River 的 `periodic` 队列、`RunOnStart`、ID 即种类，`EnqueuedKinds` 不变且有断言。
