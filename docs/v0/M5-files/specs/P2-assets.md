## 1. 目标与范围

建立 `file_assets` 及对象恢复状态，通过真实 local 字节完成申请、确认、读取签发、删除和复制；所有权限从宿主模块取得，所有存储 I/O 在业务事务与连接之外。首张表合入即接删除与清理，不通过外键级联丢失对象恢复记录。

P2 为全部用途提供准备能力。头像/封面字段引用在 P4 绑定；工作项/评论/草稿的内容引用、附件列表/计数/动态和发布迁移在 P5 接入。`uploaded` 仅表示实物已验证并封存；是否可被宿主成员看见还取决于绑定和宿主授权。不得把本阶段的准备件验收写成完整附件页面已可用。

## 2. 已确定合同

### 2.1 状态与存储

- 沿用 P1 的六个存储小端口、u/o 随机 key、用途隔离 MAC 与 `/static/local`，不重新设计传输或放宽普通 API。
- pending 申请先在事务里记录 staging，再返回上传签名；complete 先记录每次独立候选，再做实物检查/条件 Seal，最后重验宿主及资产状态，只有一个 final 胜者。失败候选保留清理依据。
- storage_metadata 有版本，至多一个 staging、一个 final 和三个尚未回收候选；不增加业务表，不接收客户端 metadata，不存无界历史数组。具体 JSON 结构、lease/回收时间值须在预检中写死。
- 两种时钟分开：签名、网络与外部操作安全期限用运行时钟；未完成/未绑定准备件 7 天、墓碑严格超过 60 天用业务时钟。
- 已上传对象不可被旧 PUT 改写；重复 complete 返回同一结果，不重复绑定或产生业务动态。旧请求的未知外部结果由独立候选和对账恢复，不能把 timeout 当成“没有写入”。
- 使用 P1 的流式读取，图片检查放入 asset/adapter/content，app 声明小校验接口，domain 不 import 解码器。校验的格式/尺寸/读取上限必须在预检中明确，不能把 DecodeConfig 声称为全图像解码。

### 2.2 API 与数据所有权

业务路由使用 design §6 的 `/api/v0/assets`、`/{id}`、`/{id}/complete`、`/{id}/content`、`/{id}/duplicate` 和 DELETE；全部走既有鉴权、严格 bodyshape、Problem/no-store。附件列表仍由 P5 在宿主快照内消费 asset 列表端口。

asset 迁移以 Plane 快照 file_assets 为起点，精确 bigint 大小、用途/父字段 CHECK、具名对象状态、上传期限与绑定事实；去除 Page、外部导入及冗余 entity_identifier。保留字段与差异逐项登记 plane-diff。本阶段不加 users/workspaces/projects 的反向资产引用列。

父 ID 必须由 owner 的实际读/授权结果确定。asset 只查询自己的表；前端从 OpenAPI 生成类型，不手写旧 Plane 形状的兼容层。P1 的 actionlessModules 登记在本段首个业务动作加入时移出，实际 Actions/规则、全路由、错误目录和两种语言文案同时补齐。

### 2.3 权限与锁序的现有事实

- 普通工作项的 `issue/app/Locks` 统一 guest HiddenFrom 次序、预检、无连接写门、P(N)、锁下重验；不能复制一套谓词到 asset。
- 评论修改限作者，删除允许作者或管理员；复用 commentCheck 与工作项可见/归档判断，不能直接等同于 issue.update。
- 草稿为作者私有；保存/删除是 W(S)→排序 P(S)→D(U)，发布是 W(S)→P(N)→D(U)。观察到宿主变化应冲突重来，锁资产后不追新父锁。
- project 写在 W(S) 下取得 P(N/S) 并重新授权；workspace 变更在 W(N) 下进行。跨源/目标复制必须一次预检、按 ID 排序全部父范围后再锁资产，不能逐个宿主递归嵌套取得锁。
- identity.Accounts/CallerLock 都规定账户行是事务的第一把锁；新签发路径需要与此协议核对，不能在持有 W/P 后才锁用户。现有 identity purge 只清 api_tokens，不清用户行，不虚构 user.deleted 事件。
- bootstrap 的现有两段组合支持先提供存储/同步删除端口，再构造拥有授权器的 owner 模块，最后构造 asset 业务用例。具体端口须拆清“读取/授权”和“父锁/叶子锁”，不传任意跨模块闭包，不在 New 后补注入。

以上是源码事实，不等同于 P2 锁图已证明。完整方法签名、排序、读快照、拒绝优先级及交错反例须在 plan 之前完成。

### 2.4 删除与清理

- 普通 issue 删除逐项发 issue.deleted；comment 删除发 comment.deleted；DeleteDraft 当前只有直接数据库删除，没有现成删除事件。必须在 owner 的原事务接入具名资产删除协作，同时保持原 At/By 与失败回滚。
- 项目/工作区批量删除不发逐项 issue.deleted；订阅 project.deleted/workspace.deleted，在原事务投递资产自己的有界任务。父范围删除后立即拒绝新资产授权，异步处理速度不能决定可见性。
- 父范围清理、准备件过期、候选回收、墓碑 purge 和孤立对象对账应分清职责，所有批次和单次时间有限，失败保留恢复记录；对象 I/O 不占业务连接。
- 当前 bootstrap purge 次序为 issue→project→workspace→identity。资产对象清理和资产墓碑删除须在父行物理删除前完成；失败不能通过 CASCADE 忽略，也不能在父模块写 asset SQL。
- 首张表同时延伸真实删除 fixture、目录/外键守卫、furnishIssueRows 与 M3/M4 删除故事；不加豁免，不把只造一个 UUID 当实物生命周期证明。

## 3. 必要验证矩阵

| 性质 | 必须有的区分数据/故障 |
|---|---|
| 完整链与重复 | 真实 PUT→complete→content→GET 字节/摘要；重复 complete 只有一个 final |
| 作用域 | guest 自己/他人、管理员兼 guest、私有项目、评论作者/管理员、草稿作者、归档/删除；不可见与不存在逐值一致 |
| 撤权/换宿主 | 在等待父锁期间撤权/改项目，锁下重判；已有资产 scope 与预读不同不追锁 |
| 外部 I/O | 阻塞检查/Seal 时请求不占事务/连接；外部成功后 DB 提交失败仍留候选 |
| 发布竞争 | 两个不同候选、相同大小不同内容、旧 PUT 重放、删除先/后，只有一个可读 final |
| 复制 | 源无权/目标有权、源有权/目标无权、跨项目正反 ID 次序、源变化、复制成功但 DB 失败 |
| 删除图 | 子树、多层宿主、邻域实物；同步回滚不留资产变化/任务，异步审计不被重试重写 |
| 清理 | 7 天/60 天严格边界、两时钟错位、迟到 PUT、失联后到对象、有界分页、未知对象与邻域独占根 |
| 契约 | 精确 raw+业务路由/动作/错误集合，原 JSON/传输期限和目录守卫继续有效 |
