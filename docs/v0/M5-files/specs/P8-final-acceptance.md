## 3. 局部裁定与合同补充

1. **粘贴（T2）**：剪贴板文件分三类：全是非图片文件为“普通”，通过校验的图片为“接受”，其余为“拒绝”（超数、超限、空 MIME、SVG 等不支持的类型、目录、图片与普通文件混合）。接受：`preventDefault` 并插入图片（不变）。拒绝：出一次 `role=alert`、`preventDefault` 并返回 true，不插入任何内容。普通：返回 false，由 ProseMirror 的粘贴管线处理其中的文字/HTML，不出提示（M5 设计 §6“编辑器不再接收自己无法插入的非图片 MIME”）。有图片能力时任何分支都不再“返回 true 却不拦下”，浏览器原生粘贴不会绕过 ProseMirror 把文件名或外部 `<img>` 写进文档；无图片能力（只读、无 write、能力已结束或禁用图片）的路径不变。拖放（`handleDrop`）不变：被拒与普通文件的拖放仍不拦下（设计“不吞掉文件拖放”）。P7b 编辑器子合同 §3 的“混合普通文件整批拒绝并保持事件未处理”与 §5 的“普通PDF、混合PNG+PDF…均不吞”按此改写（粘贴的混合批改为拦下，拖放不变），`editor-images.test.tsx` 中对被拒批断言 `defaultPrevented=false` 的原用例随合同改写。
2. **传输寿命（T3）**：图片传输属于“编辑器中带此 `id` 且 `src` 为空的节点”，不属于某个节点视图。传输记录（控制器、阶段、结果）放在扩展存储，节点视图只订阅。视图销毁时，若同一编辑器文档在当前任务结束时仍有该节点（拖动是一次删除加插入的事务，包裹/解除包裹块同理），传输继续，新视图接上原阶段与结果；节点离开文档（删除、换 `id`、Undo 撤掉插入）、编辑器销毁、`images.signal` 结束或用户取消时才取消。完成时按 `id` 与 `src` 为空在当前文档中定位节点写回 `src`（沿 `paste.ts` 按 `completed` 写回的做法）；找不到则丢弃结果并按既有规则释放。Redo 恢复的已取消节点显示可见的“传输已取消，请重新选择”状态，不显示无提示的空选择框，也不自动重发；未知复制结果仍不自动重发。
3. **核验不重建（T4）**：核验保留输入期间编辑器实例不变：输入被宿主阻止（`inert` 与只读守卫），不切换 `editable`。核验时仍在传输的图片按既有“未完成”规则报告，不取消、不丢 File；传输完成后可再次保存。
4. **删除核验（T5）**：未知 DELETE 经核验得 404 时，该 ID 离开 `uncertain`，对话框只说明“文件已不可见、无需删除”并只留关闭；不生成删除收据、不伪造 204、不触发权威重读之外的写入。`ConfirmedContentNotice` 只描述最近一次已确认结果：同一宿主开始新命令，或正文重挂载且焦点已归还后清除。
5. **提示（T6）**：普通副本未知发布经核验已不在草稿中时，关闭弹窗提示核对工作项，不提示“草稿已保留”。链接创建/更新表单的成功提示今天由表单自身 scope 守卫，写后规范重读撤下正文时表单卸载，提示被跳过；改为以宿主保留的输入状态 scope（`IssueDetailInputState.current`，正文撤回期间仍存活）判定，宿主 scope 已结束则不提示，写入与列表结果不变。子项/关联经选择弹窗提交，M4 起就只有失败提示，不新增成功提示；P7b 记录中“子项/关联提示被跳过”的说法随之更正。这是 M4 代码的本地修复，单独提交、可回退，在阶段记录、`frontend-changes` 与 M4 交接登记。
6. **删除而非转交（T7）**：`EditorRefApi.copyMarkdownToClipboard` 没有产品调用方（只有一个断言它未被调用的测试），按“删除不用的代码”删除方法、类型与该测试绑定；M4 交接的具名风险以“方法已删除”结束，后续复制一律走 `getMarkDown` + `useCopyText`，不写成“已修复”。`app/assets/attachment/` 的 17 个 PNG（含 4 个第三方标志）没有任何引用，整目录删除即满足 M1 交接条件；附件控件已用图标库的中性图标。`WorkspacePatch.Logo` 无赋值者，删除字段。
7. **告警（T8）**：选 `eslint(valid-typeof)`（4）与 `eslint(no-constant-binary-expression)`（5）全仓清零：现有命中都是 `typeof window === undefined ||` 这类恒假分支及恒真 `|| ""`，删除死分支不改变浏览器行为。两条规则在 oxlint 配置设为 error 防止回流；web cap 67→58，其余包不变。
8. **演练（T10）**：在真实组合服务上用现有夹具组合一次全链路演练，不为演练加产品开关或只供测试的 API；已由阶段测试证明的性质只重跑原测试，不重写同一断言。
9. **演示（T11）**：演示照 README“部署”节的 prod 步骤：`NERVE_ENV=prod`，基础配置的默认 `files`（`driver: local`、默认限速与期限），只经环境变量给数据库地址、`NERVE_AUTH__JWT__PRIVATE_KEY_FILE`（用 Node `crypto` 生成的 Ed25519 PKCS#8，不加依赖）与实例独占的 `NERVE_FILES__LOCAL__ROOT`；先 `nerve migrate up`，再 `nerve users create` 建第一个账户（基础配置关闭注册）后登录。e2e 的 `startNerve` 默认注入 test 环境与放宽的限速，演示必须经新增的显式选项不注入这些测试覆盖；阶段记录列出全部环境变量。
10. **S3 页面变体（T12）**：沿 P6/P7b，`[s3]` 页面变体在基础配置的 Chromium 运行；S3 的浏览器差异（CORS、自动 Content-Length、签名头）由 F4 在三浏览器证明（`m5-s3`）。矩阵按此标注，不写不存在的三浏览器 S3 页面原件。
11. **夹具用例（T9）**：用例追加到 `e2e/stories/smoke/s3-lifecycle.spec.ts`：子进程原错误经 `startS3Process(name, "")` 走启动校验失败得到，不启动容器；双失败在 `s3.ts` 层以可注入的清理函数（默认现有 `removeS3Container`）注入，断言 `AggregateError` 同时含启动原 cause 与清理错误。默认套件因此只增加毫秒级用例。
