## 2. 核对过的性质

- **列表引擎**：
  - 范围：筛选与分组只在项目列表，子分组同；排序两种列表都可用。
  - `appendID` 的两个分支都按字段 `switch`。分组键的规范化与两处游标键都认新词；项目列表重复给出参数回答 422。
  - 三条语句逐一相同：目录 CTE、两个筛选、名字键、分组的 `CASE`（分组一处、子分组两处）。每个筛选整体加括号，`OR` 漏不出 OwnOnly 的合取。
  - 名字键：迭代名用标量子查询，有 `cycle_issues` 的部分唯一保证一行；模块名取 `min(… COLLATE "C")`。
  - 排序：没有键的排最后（两向都如此），同键按 id 随方向排。SQL 的 `COLLATE "C"`、Go 的 `NameOrderKey` 与网页比较器的折叠一致。
  - 八个新参数在 `listParameters`、`groupParameters` 与子分组的同名函数里都复制了。
  - OwnOnly 在 `filtered` 里施加，组、子分组、格子的总数都只算可见的行。
- **目录**：
  - 只在按名字排序时取，与行在同一个只读快照；项目集合与状态、标签、负责人相同。
  - 每次排序只多一条语句，没有 N+1。
  - 名字只用来排位；游标里是调用者本就读得到的那一行的折叠键，同 `label_name`，不泄露。
  - 端口由消费方声明，planning 实现，与 `IssueTargets` 分开交出（接口隔离），bootstrap 转换。
- **共用夹具**：13 个场景。审者按 C 排序重新推了两个新场景的 id 数组，结果相符。五个消费者一致；e2e `i4` 共 27 个排序。生产目录的空 `Map` 加上大声失败的检查，是走不到的受守路径，不是桩或开关（R9）。
