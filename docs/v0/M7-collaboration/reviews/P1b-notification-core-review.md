## 1. 交付

- 表 `notifications`（`00049`，19 列，部分唯一的幂等键 `(event_id, change_seq, receiver_id)`），新模块 `notification`（只经端口；`actionlessModules` 里，P1c 加动作时移出），60 天清理的次序 asset → notification → issue → …（目录 32 → 33）。
- 生成：订阅者 `notify_on_issue_events` 在写的同一事务投 `notification.fanout`（一次发布的一批事件一次批量插入，R12）；任务在事务外以 `FOR SHARE` 锁工作项行（已删除则什么都不写），之后只做不加锁的读，按此刻的 `issue.read` 与只看自己批量复核收件人（`DecideMany`），一条 `INSERT … ON CONFLICT DO NOTHING`。参数保留事件变化的全部位置、HTML 置空。
- 删除：工作项删除在原事务软删它的通知；项目、工作区删除为每个项目投 `notification.delete_rows`，等该项目的工作项都被软删（500 毫秒 snooze，1 小时上限后报错）再分批软删（R3：分发不锁项目行）。
- issue 交出 `IssueRowLock`（`ShareIssue`）、`ProjectIssuesRemain`、`SubscriberIDs`、`NotificationIssue`、`CommentText`；关联的两个事件追加 `requested_on`（R11）。access 的 `DecideMany`，workspace、project 各一条批量读。
- R12：`shared` 的事件总线加批量发布（`EventBatchPublisher.PublishAll`、`EventSubscriber.HandleAll`），自动归档每个项目一次发布，`platform/jobs` 的 `InsertManyTx`。
- e2e：删除故事经接口种通知行；测试容器的连接上限按工作进程数核算（关闭 M8 交接 M6-M8-03）。
