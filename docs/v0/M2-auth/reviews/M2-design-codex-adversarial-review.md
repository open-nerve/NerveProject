## 2. 总体结论

**不建议把 `498735d` 原样作为 P1 的实施基线。** Critical 为 0；但有数项 Important 会使安全目标落空或使后续 M 返工。先改 P1 要固化的公共约定：请求与 OpenAPI 的一致性、sqlc 的跨模块迁移归属、共享游标边界、统一时间来源、`shared.Error` 的可编译接口，以及 P1 的交接关闭口径。P2 前修旧刷新令牌真实性和认证前限流；P3 前修重置密码与签发竞态。A4 的验收文本需在 P2 开始前改正。

现稿的阶段顺序（P1 平台与注册、P2 会话、P3 账户接口、P4 前端认证、P5 个人设置）是合理的；不需要拆掉 `identity` 单模块，也不需要推翻“使用方声明端口、组合根接线”。“默认拒绝 + 公开集合/路由集合/无令牌响应”三个整程序测试能覆盖**已注册的操作**，前提是以后每个 M 继续维护这些测试；没有证据说现方案存在确定的未来路由绕过。路径或查询参数在认证前绑定的 400 是文档明示的边界，不把它误报为业务 handler 可绕过认证。

M2 到 M3 的“资料可用、工作区创建失败”可以作为内部里程碑过渡，因为工作区明确不在 M2 范围内，文档也没有把 M2 说成可独立发布的成品；但现有 onboarding **挂载时**已发旧接口请求，需按 I-11 修正。现有 A1–A16 覆盖范围大体完整，A4、A7 的验收口径仍需改；A12 已写明按负责人裁定。

## 3. 新发现

### Critical

没有在现有证据下足以定为 Critical 的新发现。下列并发恢复问题后果严重，但要求旧密码或 PAT 已泄露并命中竞争窗口，且 M2 实现尚不存在，故列为 Important（高）。

### Important

**I-1｜安全／管理员重置密码不能保证赶走并发签发的凭证。** 位置：M2:282、899–916、1292–1302。证据：**设计推演**。普通登录明确“只插入一行会话”；交错为“读旧哈希并验证 → reset 在事务里改哈希并撤销现有会话/PAT后提交 → 登录插入新会话”。重新哈希路径还可能用旧密码覆盖 reset 的新哈希。PAT 创建的认证也先于用例；旧 PAT 在 reset 前通过认证、reset 后插入新 PAT，同样逃过批量撤销。影响：M2:213 所称管理员 reset 作为账户被盗后的恢复手段，按现稿无法保证生效。选项：① **推荐**签发与 reset/改密采用同一用户行锁协议，耗时的密码验证可在事务外做；锁内比较当前哈希与验证过的快照，重查账户状态及调用凭证，再插入；② 使用账户凭证版本，锁内核对旧版本并原子签发。加可控交错的真实数据库测试，不能只测顺序执行。

**I-2｜安全／只凭旧代数撤销会话，未证明旧刷新令牌是真的。** 位置：M2:167–169、185–197、1242。证据：**规范模型已复现**（第 1 节），尚无服务端可复现。从一枚已过期 JWT 读 `sid`，拼 `g=0` 和任意 32 字节；会话只要轮换过一次，`g < generation` 就撤销，密文不匹配也无妨。影响：已过期访问令牌仍具有最长到会话绝对期限的远程退出能力；不是账户接管，但 M2:196 的“持有访问令牌更严重”没有覆盖令牌过期后的时段。选项：① **推荐**保存历史刷新令牌哈希直到会话到期，确认旧哈希命中后才撤销；② 给令牌封套加独立持久 HMAC，先验证真实性再比较代数；③ 只留上一代哈希、只检测上一代重用，并明确缩窄合同。单靠 `sid` 与代数不能鉴别旧令牌。

**I-3｜安全／无效 Bearer 的匿名限流发生在验签和查库之后。** 位置：M2:341、347–350、893–903。证据：**读设计确认**。流程先认证，再选限流键；失败时的 `anonymous` 桶即使已满，第 121 次及此后的请求仍先完成 JWT 验签或 PAT 哈希查询。影响：429 不限制这段可被滥用的工作，与 M2:347 的解释相反。选项：① **推荐**在认证前增加按可信客户端 IP 的宽松成本预算，认证后仍做按凭证业务限流；② 认证前检查临时失败封禁，失败后扣减额度。须权衡团队共享出口 IP，并用计数假认证器断言超限请求根本不调用认证器。

**I-4｜安全／刷新令牌泄露可派生长期 PAT，风险上限描述失真。** 位置：M2:213–215、698、1260–1268、1280。证据：**读设计确认 + 攻击链推演**。刷新令牌可换访问令牌；创建 PAT 不要求密码、`expired_at` 可为空；退出、重复使用检测、30 天会话到期和用户自己改密均不撤销 PAT，PAT 又能创建 PAT。影响：M2:1261 只列会话终止条件，容易被误读为泄露影响最多 30 天；实际上可能延续到主动撤销恶意 PAT 或管理员 reset。选项：① **推荐的最低修订**保留现有产品行为，但写明派生 PAT 的长期风险和恢复步骤；② 创建 PAT 时重验密码，这会改变已裁定的免密码行为和自动化调用需求，需负责人裁定；③ 限制 PAT 派生 PAT 并设置到期上限，同样是产品取舍。单独限制 PAT 到期、仍允许无限派生并不能解决问题。

**I-5｜前端安全／另一标签页登录新账户后，旧标签页可持有错误的页面身份。** 位置：M2:990、997、1023–1032、1053。证据：**设计推演**。方案只处理 refresh token 被删除；例如 A、B 两个标签最初都停在登录表单，分别提交不同账户，B 的刷新令牌覆盖 localStorage 后，A 仍可显示账户 A 的 store 和内存访问令牌。A 下一次续期改用 B 的刷新令牌，后续写操作可能落到 B，页面还显示 A。选项：① **推荐**在共享记录中加入会话身份或登录 epoch，收到**换会话**事件时清空 access token/store 并重取 `/me`，同会话轮换只更新令牌；② 每次 storage 变化都重新核对 `/me`，实现简单但请求更多。P4 加两个账户、两个标签页的验收。

**I-6｜接口契约／生产服务接受 OpenAPI 明确禁止的请求。** 位置：M2:391–404、780–789；总体:145–150、519–535。证据：**读设计确认**，现稿自己承认：未知字段被忽略，`PATCH /me {"first_name":null}` 被当“未传”并返回 200；`additionalProperties:false` 和不可为 `null` 却在契约中禁止。`CheckRequest` 只检查测试发的请求，TS 类型只约束本仓库前端，均不能约束公开 API 的其他调用方。影响：这是后续所有 M 复用的错误先例，外部调用者会得到与接口描述相反的成功响应。选项：① **推荐**在 HTTP 边界做结构校验（未知字段、显式 null、必填存在性），取值规则仍留领域层；可用专门生成的解码/校验代码，不必把 kin-openapi 链接进生产；② 将契约改成服务实际的宽松语义，并取得总体设计变更认可。不能把“测试侧验证”当成服务端契约保证。

**I-7｜架构／sqlc 的模块 schema 规则缺少跨模块 ALTER 的归属法。** 位置：M2:492–504、665、1681；总体:317–323。证据：**读代码确认 + 具体推演**。sqlc v1.31.1 的 `ALTER ... ADD COLUMN` 先寻找目标表；若 M5 的 `asset` 迁移给 `users` 补 `avatar_asset_id`，其仅含 asset 表的 sqlc schema 无法解析该 ALTER；identity schema 也看不到列。选项：① **推荐**按被改表的所有权命名并拆迁移：M5 先建 asset 表，再由 `*_identity_*` 迁移修改 users；把跨模块外键/数据迁移的执行顺序写成范例；② 使用完整 schema，另以 SQL 分析规则限制查询表；③ 有理由的例外。当前规范不宜宣称 M3–M7 可直接照抄。

**I-8｜数据一致性／嵌套 `onboarding_step` PATCH 未规定原子合并，存在丢更新路径。** 位置：M2:507–508、676、789、1296–1302。证据：**设计推演**。若 A/B 同读四个 false，分别改 `profile_complete` 和 `workspace_create`，领域层合并为两份完整 JSON，再用整列 `CASE` 更新，后写者会恢复先写者的键。列级 CASE 只保护**其他列**，不保护同列中未传的键；现稿也未规定行锁。选项：① **推荐**领域层校验部分对象后用 SQL `onboarding_step = onboarding_step || $patch` 原子合并并 `RETURNING`；② 事务内 `SELECT ... FOR UPDATE` 后合并。加入两请求改不同键的真实数据库断言。

**I-9｜后续 M 约定／共享游标固定 `(created_at,id)` 不支持已批准的排序。** 位置：M2:150、450–453；总体:180–190、302–312、647。证据：**读设计确认 + M4 推演**。M4 工作项按 `sort_order`、优先级或日期排序时，用创建时间游标截下一页会重复或跳过记录。选项：① **推荐**`shared` 只定义不透明游标的版本与编码，各列表按排序方式决定载荷及稳定的 id 尾键；PAT 的载荷才是 `(created_at,id)`；② 把当前游标限制在 identity，M4 再做公共封装。不要把 M2 第一个列表的排序提升为所有列表的约束。

**I-10｜后续 M 约定／业务时钟与 `updated_at` 的用途被错误切开。** 位置：M2:478、507；总体:302–312、647。证据：**读设计确认**。现稿称审计列由数据库 `DEFAULT now()` 填、没有逻辑用它们判断；总体设计却要求 M4 按“超过 `archive_in × 30` 天未更新”自动归档，必然读 `updated_at`。`DEFAULT` 也不会在每次 UPDATE 时自动更新。选项：① **推荐**应用从同一 `Clock` 取时刻，创建与每次业务更新显式写审计列，数据库默认只作兜底；② 全由数据库计时，并补可固定数据库时钟的测试机制。把这条在 P1 写成全局规则，避免 M4 测试与线上时间来源分裂。

**M-1｜接口错误码：`limit` 取值错误没有契约落点。** 位置：M2:391–400、450–453、769、415–416。证据：**读设计确认**。`limit=0/101` 能通过整数绑定，却违反 1–100；若领域层返回 422 `validation_failed`，此操作未声明该码。选项：① **推荐**给列表操作声明 422 与 `out_of_range`，测 0、101 和非整数三类；② 将查询参数取值错误统一定为 400，并同步修改全局规则。

**M-3｜数据库约束：邮箱 CHECK 的说明不成立，JSON 约束尚可加强。** 位置：M2:647、676、1300–1301。证据：**读 SQL 表达式确认**。`email = lower(email)` 不禁止首尾空白，不能像文字所说保证“去掉首尾空白、转小写”的全部规范化。`onboarding_step` 的 CHECK 确实保证四键存在；布尔值由领域层保证，文档对此没有误述，但数据库目前会接受键值为 null/字符串或多余键。选项：① **推荐**补邮箱的 `btrim` 检查；同时考虑为四键布尔类型与键集合加 CHECK，并测反例；② 明确这些 JSON 不变量只由领域层保证，数据库约束仅覆盖键存在。

P1 的“认证安全网与第一个私有操作一起合并”、P2 的会话逻辑单独评审、P3 的 PAT 与 River、P4/P5 的前端分段，顺序成立。完成线目前有三处不能照字面证明目标：P2 的 A4（I-12）、P3/P5 的 A7（M-6）、P4 资料步骤未排除挂载即旧 API 请求（I-11）。浏览器核对能补单测无法观察的局域网非安全上下文、CSP、主题下拉定位和控制台告警；它是额外证据，不能替代确定性并发/数据库测试。localStorage 租约非原子与响应丢失导致误判重用，现稿已如实承认；A4 和浏览器抽样只能观察常见竞态，不能证明永远互斥。

## 6. 做得好的地方

- 第二稿把默认拒绝与公开操作集合、路由集合、无令牌响应放在 P1 同时落地，且通过 `PublicOperations()` 保持模块声明清楚。`identity` 单模块与 `app` 层小端口、组合根接线符合现有 M0 代码，不为认证虚增模块。
- Ed25519 JWT 限定算法、强制 `exp`、每请求核对会话；PAT 存哈希、单次显示；会话使用绝对期限；管理员 reset 连 PAT 一起撤销，这些在当前边界内有清楚的安全理由。argon2 并发名额和等待上限把过载与调用方限流分开。
- Plane 列快照、删列清单、密码规则差异、`last_used` 降写频率、CSP 外部来源均有具体依据。NCSC 名单的 SHA、过滤规模和示例可复核；许可仍须在 P1 对**具体数据文件**核实，[NCSC 条款](https://www.ncsc.gov.uk/section/about-this-website/terms-and-conditions)和[开放政府许可](https://www.nationalarchives.gov.uk/doc/open-government-licence/version/3/)均提醒第三方权利不能只凭网站总条款推定。
- `x-problem-codes` 的操作级声明、PAT 对等、真实数据库断言、整程序路由核对以及控制者浏览器核对，让后续 M 有一套可继承的证据链。M2/M3 过渡不能建工作区已在文档中坦白，不把失败伪装成成功。
- 账户枚举的处理有明确边界：登录用假哈希拉齐未知邮箱的主要计算路径，停用状态只在密码正确后告知；注册仍可探测，文档如实披露并按 IP 限流（M2:309–316、1203–1206）。argon2id 的 19,456 KiB、2 次迭代、4 个并发名额和 2 秒等待有过载边界；性能数值仍需按 P1 完成线实测。
- 前端清理旧 Cookie/CSRF 调用后使用 Bearer；访问令牌以响应到达时刻加秒数计算有效期，避免与服务端时钟直接比较。CSP 对脚本采用内联哈希，且列出后续 M 的外部来源。`navigator.locks` 缺失时租约不是互斥原语，现稿承认最坏情形会触发重新登录；它是 P4 浏览器核对和后续运行中须持续观察的剩余风险（M2:990–1018、1035–1046、1208–1236）。
