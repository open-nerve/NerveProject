## 2. PC1：公开项目非成员的图片读取失效

审者发现草案同时要求“沿唯一权限失效入口”和“不修改权限观察器”，但现有观察器对合法可见的公开项目非成员无法提供可见性代次。主控以实际 RootStore、ProjectStore、UserPermissionStore 和 IssueRootStore 联合复现：完整目录移除项目后，member_role=null 的旧读取仍 current=true；恢复后依然 true，invalidate 为 0。member_role=15 的控制组缺席/恢复均 false、invalidate 为 1。

按 P6 新合同断言得到 1 failed/1 passed，失败均为上述生命期断言，非编译失败；4434 个非文档输入前后未变。初次探针配置误用 Vitest CommonJS 入口产生的 0 tests 原日志另存，不计为行为 RED。非成员的工作项读取仍被拒绝，现有授权角色不能为图片显示而伪造成成员。

该发现要求扩展 M4 共享失效事实范围或缩小 P6 展示验收，属于负责人要求先提交上报的跨模块边界。[决策记录](../v0/M5-files/reviews/P6-public-project-lifetime-decision.md)给出 A/B、根因、收益、风险与完整回归落点。PC1 未决前不改 M4 设计和产品、不声称预检通过，也不启动 T1。

## 3. 独立的局部决定与代价

1. raw PUT 用独立 fetch，credentials=omit、redirect=error、no-referrer，实际 File 作为 body；阶段进度不冒充字节进度。三浏览器隔离协议探针证明 XHR.withCredentials=false 仍发送同源 Cookie，而该 fetch 不发送 Cookie/Auth/Referer，308 不跟随。它不是 P6 产品页面验收。
2. P6 新增 AssetService 的当前消费者方法；旧 FileService/services 包在 P7 最后编辑器/评论消费者迁移时删除。保留一个阶段的代价明确，M5 总体删净条件和关键词守卫不变，不复制旧 multipart helper。
3. 上传资源由视图拥有；宿主绑定仍属于对应页面/宿主 store。资料图片共享活动来源读取，实体与权限事实不复制；既有宿主网络读/写可能完成，失效资源不得发布 URL 或继续反馈，不宣称已撤销服务端写或已发出的存储能力。
4. UserStore 使用已有 Reconciled 局部协调新并发读取，不改公共原语。新建项目在原创建弹窗内嵌封面内容，取消本地旧延迟 reset，不改 shared ModalCore/动效/全局按键。
5. 29 个封面由项目自制 SVG，稳定 ID；只响应明确随机操作。公开邀请沿原 link key 与预览接口；guest 不因头像占位而请求禁止的成员接口。M6/M7 叶子呈现可换共用头像，不恢复未实现接口。
