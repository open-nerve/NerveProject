## 4. 三视角复核

**逻辑：** 上传只指 staging，封存使用每次独立候选，最终字节不受旧 PUT 影响；DB/存储不假装同一原子事务，metadata/对账承接外部残留。local 同 key 第二 PUT 拒绝与未来 S3 staging 可重写是允许差异，共同合同只要求最终封存不变。P1 不提前宣称业务准备件或清理完成。

**集成：** 既有 MAC、API 中间件、模块边界、草稿锁序和父删除事件均有明确接入点；资料/项目引用迁移归所属模块；所有文件状态变更、事件、任务按同事务或外部 I/O 的实际边界划分。后续 owner 端口的具体签名/锁图属于 P2/P4/P5 预检，不能用当前总体设计代替。

**覆盖：** P1 A1–A10 映射到 11 个 Task；Review Focus 的五类易漏输入均分配到实际测试文件/测试名。真实 slow stream >30 秒和 >1 MiB、raw route 精确集合、普通 JSON 限制、签名字段变异、字节变化、跨世界目录和关闭释放有必要测试；在实施前没有把任何这些测试标成已通过。
