## 2. 已确认的局部问题

### R01：测试服务启动失败后，清理重复接收退出结果而永久等待

- 严重度：Major（测试基础设施）；分类：Local Fix。
- 来源：`server/internal/bootstrap/app_test.go` 的 `runBuiltApp`，供普通 HTTP 集成、请求锁探针和规模夹具共同使用。
- 触发：服务在健康检查完成前返回错误，例如监听地址无效。
- 根因：启动轮询从 `done` 消费唯一的退出结果并调用 `t.Fatalf`；随后 cleanup 再从同一未关闭通道接收，无法继续到 `app.close`。
- 影响：原本能立即诊断的启动错误拖成整包超时，连接池清理被阻塞；产品运行路径本身没有改变。
- 红例：新增 `TestAppFixtureStartupFailureClosesResources`，在同一测试二进制的独立子进程启动真实 app，使用无效监听端口；期望普通失败退出且保留启动诊断、完成连接池关闭。
- 修复前：子进程已报告 `run() returned early`，随后 5 秒超时、退出码 2；栈停在 `app_test.go` 的 cleanup 接收处，父测试失败。
- 根因修复：运行 goroutine 结束时关闭结果通道，使启动分支消费结果后 cleanup 仍能完成；正常关闭时仍检查唯一的运行错误。
- 聚焦复验：上述新用例、自动迁移就绪、待迁移未就绪、数据库不可用、迁移失败、真实 HTTP 请求探针共 6 项，`-race -count=1` 全部通过。
- 原始证据：`t10-startup-red.{json,log}`、`t10-startup-green.{json,log}`；两次输入均未在运行中改变，日志 SHA256 见收据。
- 服务端全量回归：`GOFLAGS=-p=1 make test` 通过（459.30 秒），`make lint-go` 通过（11.87 秒）；运行输入未改变，收据为 `t10-server-test.json`、`t10-lint-go.json`。前一次误用不存在的 `make test-go` 仅为命令错误，未执行测试，原始失败收据保留且不计反证。
- 修复与调用者全文复审：启动轮询消费结果后，关闭通道使清理完成；正常停止仍消费唯一运行结果，`app.close` 的后进先出顺序不变。产品、C12 及性能工作负载代码未改变；最终输入等价仍在 T13 统一绑定。

### R02：超大正数时长相加溢出，绕过组合预算校验

- 严重度：Minor；分类：Local Fix。仅在管理员配置极大时长时触发，不涉及公开请求输入。
- 来源：`server/internal/platform/config/validate.go` 的写入等待预算与刷新预算；两个正数 `time.Duration` 直接相加可能溢出为负数，被误判为小于请求或前端截止时间。
- 影响：非法配置在启动时通过，无法保证文档约定的等待预算；默认和正常范围内的配置不受影响。
- 红例：`TestDurationBudgetsRejectOverflow` 经真实环境配置加载覆盖两项预算，各含恰好小 1 纳秒、相等、超出、单项超出及三个溢出组合；修复前 6 个溢出子例失败，其余边界正确。
- 修复：先将一个正数时长与预算比较，再将另一个时长与剩余预算比较，避免相加溢出；字段名、错误文案和合法配置语义不变。
- 复验：配置、内置配置和 CLI 三包 `-race -p=1 -count=1` 全部通过（12.80 秒），Go lint 通过（22.84 秒）。原始收据 `t10-budget-red.json`、`t10-budget-green.json`、`t10-budget-lint.json` 绑定输入及日志 SHA256。
- 全文复审：通过前置正值判断及短路比较，执行减法时被减项均处于预算内，不会产生溢出；CLI 先加载校验再启动 app。C12 与规模验收所用正常配置等价，最终二进制与输入绑定仍由 T13 完成。

### R03：级联删除测试没有接入事件观察者，零计数断言不能证明没有事件

- 严重度：Major（测试覆盖）；分类：Local Fix。未发现产品实际多发事件。
- 来源：`server/internal/bootstrap/issue_lifecycle_events_test.go` 的 `TestIssueDeletionEventsCascade`。
- 根因：普通 `newIssueWorld` 使用生产订阅者，不含 `issue_test.event_probe`；原测试仅查询此探针任务的数量，断言天然为零。
- 红例：在项目和工作区两个场景中增加正常更新的正向控制，原夹具均失败于“event observer did not see the positive control”。
- 修复：复用测试模块构造器，让同一 `issue.Module` 的 HTTP 和实际 `Jobs()` 接受同一事务事件观察者；准备数据的 app 在子测试结束时关闭，之后只有可观察 Runner 消费删除任务，避免另一个 Runner 抢先消费。正常更新先产生一个探针任务，等待真实删除任务完成后必须仍为一个，且子项均已软删除。
- 改动只涉及两个 bootstrap 测试文件，产品构造器、接口及领域依赖未改变。观察者使用真实 dispatcher 与 `InsertTx`，不替换删除用例或伪造结果。
- 复验：级联、单项/子树删除、归档事件及单连接事务写入四项 `-race -count=1` 通过（18.20 秒）；`t10-cascade-observer-red.json`、`t10-cascade-observer-green.json` 保存输入、失败原因和日志 SHA256。Go lint 通过（11.73 秒）；修复后的两个文件及模块、Runner、父级事件构造器已全文复审，生产行为与 C12 输入不变。

### R04：合法极大排序值的中点计算溢出，拖放发送 null

- 严重度：Minor；分类：Local Fix。仅在相邻工作项具有极大同号有限排序值时触发；服务端允许这些 `double precision` 值。
- 来源：`web/apps/web/core/store/issue/helpers/base-issues.store.ts` 的 `dropIssue`。先相加再除以二得到 Infinity，生成客户端的 JSON 序列化将其写成 `sort_order: null`，合法的中间拖放被服务端拒绝。
- 红例：经真实 RootStore、列表绑定、写队列和客户端检查实际 PATCH body；正极值 `8e307/1.6e308`、负极值 `-1.6e308/-8e307` 两例实际失败为 null，跨符号和次正规数两例通过。不是直接断言私有计算函数。
- 修复：加法结果有限时保留原计算，仅在和溢出时先各除以二再相加。中点含义、正常值舍入、首尾间距、队列和确认后更新保持不变，不重排其他卡片或扩大 API。
- 复验：拖动、列表、实体和变更协调四个测试文件共 214 项通过（2.42 秒、无 skip）；`make lint-web` 54/54 通过（4.63 秒）。收据 `t10-drag-midpoint-red.json`、`t10-drag-midpoint-green-2.json`、`t10-drag-midpoint-lint-2.json` 均绑定实际输入和日志 hash，运行中输入不变。
- 首次 lint 拒绝新测试的三个次正规数十进制字面量（精度规则）；改用 `Number.MIN_VALUE` 的整数倍明确构造，没有放宽 cap 或规则。原始失败保留，不计产品反证。
- 修复后的完整门面、测试、根协调器和拖动调用者已复审；T13 以新前端产物补验 C12 的 I6 拖动格，并重新绑定未受影响的证据。

### R05：更改每周开始日后，已导航到其他月份的周视图消失

- 修复：同一日历 store 清空旧周边界后，同时生成当前月和当前周所在月份的日期。保持两种导航日期独立，不改变偏好协议、共享生成函数或筛选含义。
- 复验：日历页面/选择器/快速添加、根 store 生命周期和项目筛选五个文件共 34 项全部通过（4.54 秒），`make lint-web` 54/54 通过（11.07 秒）。收据 `t10-calendar-preference-red.json`、`t10-calendar-preference-green.json`、`t10-calendar-preference-lint.json` 均保存实际输入及日志 SHA256，运行中输入未变。

## 3. 当前阅读结论

### 3.1 Issue 应用、领域和持久化

- 已逐项核对应用与领域行为、实际 SQL、adapter 与对应单元/数据库集成测试。
- 权限：显式来源授权与普通可见目录分别使用；访客只读本人创建、历史目录与普通目录的差异有正反例。
- 层级：隐藏父项以对调用者可见的投影参与比较，返回值清除不可见父项；真实递归与循环边界有覆盖。
- 写入：归档拒绝、无效输入、no-op、事务回滚与事件失败不泄漏部分写入；应用 fake 仅证明调用顺序，数据库证明原子性。
- 列表：过滤先于 LIMIT，分组和单元格各自续页，重复关联不膨胀总数，空游标页重算仍保留原范围及筛选。
- 精度：真实 SQL 与固定期望核对浮点相邻数、微秒时间、日期边界及大整数；极大计数通过表达式探针，不冒充海量种数。
- 删除：批次游标推进、关系首个删除者审计、真实锁等待和重试覆盖；purge 的逐批自动提交与边界保留按设计核验。
- 草稿：仅本人及当前工作区可读写、JSONB 全量替换与无变化审计、发布先授权后解码有覆盖。
- 链接：原 URL 唯一约束、哈希碰撞、标题独立更新与旧 URL 元数据拒写有数据库正反例。
- 本轮这些范围尚未发现新增可操作的产品缺陷；此结论不替代未完成的全期集成审查。
