## 2. 局部发现、修复与限定复审

### Major：表格菜单退役留下键盘标志（终审发现，已修复）

`web/packages/editor/src/extensions/table/plugins/drag-handles/{row,column}/drag-handle.tsx` 原本只在 onOpenChange(false) 的延迟回调移除 TABLE。选择离开表格、切只读或销毁 editor 直接卸载 widget，不经过关闭回调，公开 `EditorRefApi.isAnyDropbarOpen()` 仍为 true，影响 Enter 和 peek 关闭。

由菜单自身 effect 成对注册/释放 TABLE，随真实挂载所有者清理，不引入另一份全局状态。真实 row/column 各三个退役测试先得到六个失败，修复后 DOM portal 与公开 ref 都清理；重新进入仅一份 widget。两个外层宿主的真实页面补证：首次 Escape 只关菜单并回焦，下一次关闭草稿/peek；背景隔离保持。限定复审检查了 after-destroy 命令合同、注册/清理时机及原编辑命令，已通过。

### Major：内部控件 focus 被编辑器包装层抢回（T10 发现，已修复复审）

`web/packages/editor/src/components/editors/editor-content.tsx` 原来对所有冒泡 focus 调 TipTap focus，表格/图片按钮或 portal 得到焦点后又被下一帧抢走。只代理包装层自身的 focus；内部原生控件保持其拥有者。两项真实包装层红例及页面事件堆栈验证根因，原 tabIndex 聚焦正例保留。M21 恢复旧行为时真实列按钮 opacity=0，被原页面断言检出；恢复原字节、构建及三引擎验证通过。

### Major：行列 widget 未在实际 DOM 退役时释放（T10 发现，已修复复审）

`.../drag-handles/{row,column}/plugin.ts` 原状态变换提前创建 ReactRenderer，离开表格丢掉引用，顶层 destroy 并非 ProseMirror 的释放回调。改由 Decoration.widget 的 toDOM/destroy 管理对应 renderer，未挂载的中间 transaction 不创建 renderer；只读不提供可操作 decoration。真实组件离开/只读/销毁红绿、重新进入唯一控件、真实行列插入入库与 Back 释放覆盖了完整生命周期。

### Minor：最终静态报告与文档状态需要重新对账（终审发现，已修复）

spec 的 T1–T3/T2 待核、设计“尚未实施”已经过时；原 T4 的 358 保留项不能冒充新报告。最终 fresh typegen 后原 AST 得到 353 个 M4 候选，与旧 ledger 352 个 identity 相同；6 个旧候选因夹具移动/分类变化退出，1 个 label 重新归类并追到实际按钮读者。新增逐行 FJ 映射、更新阶段状态，M4 总完成线和八份输入交接仍开放。部分 build 后路由生成文件不全的早期扫描保留但不作终态依据。

### Minor：I11 自动输入的 DOM 选区与回焦竞争（已修复复审）

完整 F 的 I11 保存了“中文输入Confirmed comment”，原 substring 请求断言没有发现旧文字残留。真实浏览器受控释放 ProseMirror 的回焦选区同步回调，复现 DOM-only 全选折叠与后续追加；同一回调不能破坏编辑器键盘全选。沿既有 I2/I12 模式，创建重试和编辑均改 ControlOrMeta+A / insertText，提交前精确核全文，请求 HTML 精确核单段文字。三个引擎各十遍、完整 E2E 284/284 通过。没有改产品编辑器或放宽错误观察。原失败 trace、两次未捕捉竞争的诊断和有效受控复现分别保留在 `i11-root-cause.md` 指向的原件；受控实验说明原因链，不声称原 trace 包含内部回调日志。
