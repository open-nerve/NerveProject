## 2. 起点事实

- **planning**：读之路 `Reads.run` 是一个只读快照，能看到调用者的 OwnOnly；写之路 `Locks.run` 拒绝 OwnOnly、已归档的项目与开关关闭，唯一的锁是项目行。列表行与详情都没有计数，`Cycle` 也是每个写入的回答。planning 没有状态的目录，读不到状态组。
- **issue**：`cycle_issues` 部分唯一 `(issue_id)`；P3a 的写法是软删加插入；动态的构造只导出了 `CycleLeft`；删迭代的订阅者在原事务移除归属、写动态、`MarkChanged`，不发布 `issue.updated`。跨模块在同一事务里经 ctx 调用。
- **口径的原料**：OwnOnly 的谓词是“建立者为本人”（建立者为空的不算）；草稿另表；状态改组不回写工作项，`completed_at` 可能过时；年份 0001–9999，日期跨度没有上限。
- **周期任务**：自动归档是模板（候选不加锁、每项目一个事务、先锁再读时钟、每项目提交）；新种类要进六处清单与配置。
- **Plane**：有快照后 `progress` 只回答快照；燃尽按 UTC 切天、已取消永不燃尽；实时分布的“无负责人”“无标签”恒为 0；转移每次写快照并覆盖，动态因崩溃一条不写，回答 `{"message":"Success"}`；没有写快照的周期任务。

## 4. 审者核实为正确的事实（摘要）

- **R2 的分工**合 `TestSQLCSchemaScope` 与架构测试的导入规则；issue 的存储经 ctx 加入调用者的事务，读在 planning 的只读快照里、转移在 planning 的写事务里。项目的 `IssueStates` 足以给出状态组；分诊组不能设到已有状态上、在用的状态不能删，所以“范围外的组回答 500”是真正的缺陷路径。
- **可见范围**：读之路能看到 OwnOnly；冻结对 OwnOnly 为 `null` 是对的。
- **冻结**：候选的超集推理成立（已结束 ⇒ 结束日 < 项目今天 ≤ UTC 今天 + 1 ⇒ 结束日 ≤ UTC 今天）；“只在为空时写入”在项目行锁下即先写者为准；自动归档的模板各点属实；不改 `updated_at` 使既有的时刻断言稳定。
- **转移**：拒绝次序沿用 `decideOn` 与 P1/P3a 的锁下判定、时钟最后；锁序项目行 → `cycles` → `cycle_issues` → `issue_activities` → `issues` 不会成环（其他写者都先取项目行，偏好取 `FOR SHARE`，插入 `cycle_issues` 只对目标迭代行取 `KEY SHARE`）；0 个时只冻结、回答 200 合理。
- **形状**：`api/` 没有 `allOf`，`IssueDetail` 写全字段；列表行另立 schema 是对的；Go 与 e2e 现有的列表断言不因多出字段而坏，网页的类型检查成立。
- **R11**：硬规则 §4 第 4 条针对新码；两条文案经 `PROBLEM_MESSAGES` 与 `errors.json` 读取，改写成立。
- **计数与名字**：迁移 47 个、`TestCyclesSchema` 钉列与索引、sqlc 的 planning 条目、运行角色已覆盖 `cycles`、手搭 `planning.New` 的两处、六处周期种类清单、`EnqueuedKinds` 只列请求触发的种类、同码异消息的先例、apitest 按（操作，码）核对、交错工具与自动归档的锁超时/部分提交测试、e2e 的断言工具，均属实。
- **Plane 抽查**：转移工具的目标 `.first()` 与 500、每次写快照、`bulk_update`、动态任务在 `json.loads` 处崩溃；应用接口与公共接口的源规则；燃尽用 UTC 的今天；分布按 `completed_at` 是否为空。R12 的说法都成立。
